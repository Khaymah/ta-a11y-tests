# فحوصات إتاحة منصّة «طا»

مجموعة اختبارات آلية بتفحص إتاحة [ta.muslimgate.org](https://ta.muslimgate.org) لذوي الاحتياجات الخاصة على معيار **WCAG 2.2 AA**، وبتطلّع تقرير عربي واضح بالمشاكل.

## التشغيل

```bash
npm install
```

```bash
npm test
```

بعد التشغيل افتح:
- **`reports/A11yReport.md`**: التقرير العربي (الملخص، والمشاكل، وتفاصيل axe لكل صفحة)
- `npm run report`: التقرير التفاعلي فيه لقطات الشاشة لكل اختبار فشل

> المتصفح لازم يكون Chromium متوافق مع Playwright 1.63. لو مش مثبّت: `npx playwright install chromium`

## أوامر مفيدة

| الأمر | بيعمل إيه |
|---|---|
| `npm test` | كل الاختبارات (ديسكتوب + فحص axe على الموبايل) |
| `npm run test:desktop` | الديسكتوب بس (أسرع) |
| `npm run test:axe` | فحص WCAG الآلي بس |
| `npm run test:keyboard` | التنقل بالكيبورد والـ focus |
| `npm run test:player` | مشغل التلاوة |
| `npm run test:mushaf` | اختبارات المصحف |
| `npm run test:local` | نفس الاختبارات على `localhost:3000` وقت التطوير |
| `npm run typecheck` | فحص الأنواع |

### متغيرات البيئة

| المتغير | الافتراضي | الاستخدام |
|---|---|---|
| `TA_BASE_URL` | `https://ta.muslimgate.org` | تختبر نسخة تانية (staging أو local) |
| `TA_ONLY` | كل الصفحات | صفحات معيّنة: `TA_ONLY=tuhfah,mushaf npm test` |
| `TA_WORKERS` | `2` | عدد المتصفحات اللي شغالة مع بعض. خليه قليل على الموقع الحقيقي |
| `TA_RETRIES` | `0` | إعادة الاختبار لو النت مش مستقر |

أسماء الصفحات (slugs): `home` · `taiyebah` · `shatibiyyah` · `durrah` · `jazariyyah` · `salsabil` · `tuhfah` · `mutashabih` · `mushaf` · `collection` · `feedback`

| الملف | المحور | بيخدم مين |
|---|---|---|
| `tests/Axe.spec.ts` | فحص WCAG 2.2 AA الآلي لكل صفحة، وكمان بعد فتح باب من المتن، على الديسكتوب والموبايل | الكل |

| `tests/Reflow.spec.ts` | عرض 320px (= تكبير 400%) وتباعد النص (WCAG 1.4.12) | ضعاف البصر وعسر القراءة |

| `tests/UserPreferences.spec.ts` | تقليل الحركة، تكبير خط المتصفح، التباين العالي في ويندوز، الوضع الداكن | ضعاف البصر، والصرع، والـ ADHD |

### إزاي تقرا النتيجة
- **الاختبار اللي بيفشل معناه مشكلة حقيقية في الموقع**، مش في الاختبار. رسالة الفشل بتقول المشكلة إيه وفين.
- فحص axe بيفشل بس على مخالفات WCAG **الخطيرة والحرجة**. المتوسطة والبسيطة بتظهر في التقرير كتوصيات.
- الاختبارات المكتوب جنبها **(توصية)** أفضل ممارسة، مش شرط WCAG إلزامي.
- لما تصلّح مشكلة، الاختبار بتاعها هيبقى أخضر لوحده، فالمجموعة دي بتشتغل كـ **regression suite**.

## حدود الفحص الآلي

الأدوات الآلية بتمسك تقريباً **30–40%** من مشاكل الإتاحة. الباقي محتاج تجربة بشرية. شوف **[`docs/ManualTesting.md`](docs/ManualTesting.md)** فيه سيناريوهات NVDA وVoiceOver خاصة بالمتون والمصحف.

## الإضافة للـ CI

الملف `.github/workflows/a11y.yml` بيشغّل الاختبارات:
- **أسبوعياً** (الأحد الصبح) على الموقع الحقيقي
- **يدوياً** من تبويب Actions ← Run workflow، وتقدر تحدد الموقع (`base_url`) والصفحات (`only`)
- على كل **Pull Request**

التقرير العربي بيظهر في صفحة الـ run نفسها (Job Summary)، وكل التقارير بتترفع كـ artifact باسم `a11y-reports`.

> الـ workflow **تقرير بس**: بيطلع ✅ دايماً حتى لو فيه مشاكل إتاحة، وبيحط تحذير ⚠️ «Accessibility issues found» في صفحة الـ run، والتفاصيل في التقرير. بيفشل ❌ بس لو كود الاختبارات نفسه فيه خطأ (الـ typecheck).

## ملحوظة أدب

الاختبارات بتشتغل على الموقع الحقيقي، فخلّي `TA_WORKERS` قليل (2 كفاية) ومتشغّلهاش في loop. الأفضل تشغيلها على نسخة local أو staging.
